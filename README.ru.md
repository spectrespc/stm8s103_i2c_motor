# STM8S103F3P6 — контроллер двух шаговых двигателей (ведомый I²C)

> 🇬🇧 [English version](README.md)

## 1. Быстрый старт
- Требования: SDCC ≥ 4.0, STM8-SPL-SDCC в ~/STM8-SPL-SDCC, stm8flash, ST-LINK/v2
- Сборка: `make clean && make` → build/firmware.ihx
- Прошивка: `make flash` (или `stm8flash -c stlinkv2 -p stm8s103f3 -s flash -w build/firmware.ihx`)
- Проверка: `i2cdetect -y 7` (должен показать 0x60)

## 2. Возможности
- Ведомый I²C, адрес 0x60, стандартный режим 100 кГц
- 2 биполярных шаговых двигателя: focus + zoom, управляются напрямую двумя
  H-мостами DRV8833 (полношаговый режим, обе обмотки под током)
- Генерация шагов DDA с периодом 1 мс в обработчике прерывания TIM4
  (1–5000 шагов/с), без STEP/DIR
- Сторожевой таймер IWDG ~500 мс, перезагружается в основном цикле и в ISR TIM4
- Сохранение позиции в EEPROM с CRC16
- Мониторинг nFAULT (перегрузка по току/тепловая защита/UVLO) → защёлкнутое
  состояние ERROR, двигатель обесточивается
- Восстановление после ошибок I²C (AF/BERR/OVR → программный сброс, таймаут 2 с)
- HSI 16 МГц, без внешнего кварца

## 3. Требования к аппаратуре
- **Внешние подтягивающие резисторы на PB4/PB5 (I²C): 4.7 кОм к VDD — ОБЯЗАТЕЛЬНО**
  (истинный открытый сток, внутренних подтягивающих резисторов нет)
- Драйверы шаговых двигателей: 2× DRV8833 (по одному на двигатель), плюс
  конденсатор 0.01 мкФ на VCP и накопительный конденсатор 10 мкФ на VM на каждый чип
- Питание: 3.3 В или 5 В (STM8S103 допускает 2.95–5.5 В); VM DRV8833 2.7–10.8 В
- Программирование SWIM: подключить PD1 к ST-LINK SWIM, NRST к ST-LINK RST

## 4. Карта выводов
Авторитетная карта выводов TSSOP20 и назначение сигналов проекта находятся в
[docs/HARDWARE.md](docs/HARDWARE.md). Учтите, что PB0–PB3 отсутствуют на корпусе
TSSOP20, поэтому все сигналы обмоток/nSLEEP/nFAULT используют порты A, C и D.

## 5. Краткое описание протокола I²C
Полный справочник команд (полезная нагрузка, порядок байтов, размеры ответов)
находится в [docs/PROTOCOL.md](docs/PROTOCOL.md). Коды команд — 0x01–0x06 и 0xFF
(команда calibrate 0x07 удалена в 2.0.0).

## 6. Сборка из исходников
Для проекта требуются:
- Компилятор SDCC (версия 4.0 или новее)
- Библиотека STM8-SPL-SDCC в каталоге ~/STM8-SPL-SDCC
- Программатор ST-LINK/v2 для прошивки

Исходники организованы в функциональные модули:
```
src/
├── core/   main.c, main.h, stm8s_conf.h
├── hal/    hw_config.c/h, stm8s_it.c/h
├── i2c/    i2c_slave.c/h, i2c_proto.h (shared command table)
└── motor/  stepper.c/h, stepper_logic.h (pure DDA/phase), eeprom.c/h
```

Для сборки прошивки (запускать из корня репозитория):
```
make clean && make
```

Прошивка будет создана как build/firmware.ihx. Все промежуточные артефакты
(.rel, .asm, .lst, .map, ...) записываются в build/ и не отслеживаются git.
Host-тесты протокола находятся в tests/ и запускаются командой
`make -C tests test`.

## 7. Тестирование
Основные команды проверки:
```bash
# Check I2C device is present
i2cdetect -y 7

# Get firmware version
i2ctransfer -y 7 w1@0x60 0xFF r3

# Move focus motor +100 steps
i2ctransfer -y 7 w4@0x60 0x02 0x00 0x01 0xF4  # set speed
i2ctransfer -y 7 w4@0x60 0x01 0x00 0x00 0x64   # move

# Get focus motor position
i2ctransfer -y 7 w2@0x60 0x04 0x00 r4

# Get focus motor status
i2ctransfer -y 7 w2@0x60 0x05 0x00 r1
```

## 8. Известные ограничения
- Разомкнутый контур: позиция ведётся только программно (нет обратной связи по
  энкодеру). Заблокированный/пропускающий шаги двигатель обнаруживается только
  через nFAULT (перегрузка по току), а не по потере позиции.
- Нет разгона/торможения
- Движение игнорируется, пока не задана скорость (сначала `motorctl speed …`)
- Ресурс EEPROM: запись ограничена ≤ 1 Гц и пропускается, пока двигатель работает

## 9. Устранение неполадок
- Ошибка SWIM 0x04: проверьте питание, подключение SWIM, NRST (PD1 не должен быть нагружен)
- I²C не обнаружен: проверьте внешние подтягивающие резисторы на PB4/PB5
- Двигатель не вращается: сначала задайте скорость, затем движение; проверьте подключение nSLEEP DRV8833
- Двигатель сразу сообщает ERROR: проверьте nFAULT DRV8833 (КЗ/перегрузка по току)
- Цикл сброса WDT: убедитесь, что вызывается IWDG_ReloadCounter()
