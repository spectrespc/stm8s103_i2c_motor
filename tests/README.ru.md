# Тесты

> 🇬🇧 [English version](README.md)

Host-тесты (Linux + gcc) логики обработки команд I²C.

## Запуск

Из корня репозитория:

```bash
make -C tests test
```

или из этого каталога:

```bash
make test
```

Бинарный файл тестов выводит количество успешных/неуспешных проверок и
завершается с ненулевым кодом, если какая-либо проверка не прошла.

## Область охвата

Код протокола прошивки (`src/i2c/i2c_slave.c`) обращается к регистрам STM8 SPL
(`I2C->SR1`, `GPIO_*`, `sim()`/`rim()`) и не может быть слинкован на host-системе.
Поэтому `test_i2c_protocol.c` проверяет ту же чистую логику. Общие определения
берутся напрямую из заголовков прошивки, чтобы они не расходились:

- коды команд и таблица длин (`i2c_required_len`) — из `src/i2c/i2c_proto.h`
- ограничение скорости (`MAX_STEP_SPEED`) — из `src/core/main.h`
- ограничение скорости (clamp) и защита от переполнения при движении — из `src/motor/stepper_logic.h`

`test_stepper_logic.c` покрывает ядро шагового двигателя напрямую: таблицу
полношаговой коммутации, фазовый секвенсор, накопление шагов DDA (включая
арифметику с базой 1000 при 1 мс и ограничение 5 шагов/тик при 5000 шагов/с),
границы скорости и защиту от переполнения int32 цели. Тестируемые функции — те же
хелперы `static inline`, которые использует `src/motor/stepper.c`.

Оставшийся хелпер в `test_i2c_protocol.c` продублирован и должен поддерживаться в
синхронизации при изменении протокола:

- разбор полей 16/32 бит в формате big-endian и смещение полезной нагрузки команды

## Файлы

- `Makefile` — собирает и запускает тесты (не используется сборкой прошивки)
- `test_i2c_protocol.c` — тесты команд/протокола I²C
- `test_stepper_logic.c` — тесты DDA / коммутации шагового двигателя
